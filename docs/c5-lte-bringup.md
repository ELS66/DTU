# C5 0.3.0-dev：4G TCP与新连接选路联调

> 本文记录0.3.0-dev的AT TCP基线。当前0.4.0-dev按用户确认改为绿灯网络就绪、蓝灯MQTT，MQTT后端接入等用户文档，优先板内控制；最新灯规则和待办见[板内控制清单](c5-board-control-requirements-v0.14.4.md)。

日期：2026-10-20。硬件V0.14.4，ESP32-C5、ML307R-DL；ESP-IDF 5.5.1。

## 本轮范围和验证结果

本轮在0.2.0-dev的TTL/余时记录、双频Wi-Fi和SmartConfig之上，增加ML307R注册/PDP管理、AT TCP单连接适配、Wi-Fi优先的新连接选路，以及台架TCP连接/回显诊断。源码已交叉编译，2693项生产C核心检查通过；电脑端回显工具的2073字节二进制往返冒烟检查通过。

尚未烧录实板。SIM真实注册、APN与PDP激活、目标服务器收发、异步AT时序、无硬件流控压力和2.4/5GHz均待验证。本版是普通TCP台架实现，尚未加入TLS证书校验、云端认证/MQTT、周期性网络健康探测或OTA，不能作为量产云端通道。

## 厂家资料及型号边界

用户工作区资料目录为ML307R/01_文档资料/ML307C（中移AT版本）AT命令手册。目录名称含C，但其中以下通用手册的适用型号表明确列出ML307R-DL：

- AT_Commands_Reference_Guide_4G_Series_V2.0.5：型号识别、CSQ、CEREG、CGATT、CGDCONT、CGACT、CGPADDR等标准命令。
- TCP_IP用户手册_V5.1.5：MIPCFG、MIPOPEN、MIPCLOSE、MIPSEND、MIPRD、MIPSTATE与MIPURC。

重点核对了TCP/IP第14～19页配置与型号脚注、第22～31页连接/关闭/HEX发送/缓存读取、第34～35页连接状态、第60页异步通知。ML307R不支持MIPCLOSE的mode参数，代码只发AT+MIPCLOSE=0。通用AT第95～98页要求指定CID、保留最后一条承载等限制也纳入实现。

资料包另有ML307C专用拨号文档和ML307C固件。它们不构成当前板卡UART PPP或刷入C固件的依据；本轮未安装模组驱动、未刷写基带固件。实际运行时通过CGMM/CGMR报告型号和版本，未识别出ML307R时保留诊断并禁止数据操作。证据路径和文件哈希见[c5-lte-evidence.json](c5-lte-evidence.json)。

## 4G状态与激活

1. 延续先探测AT、失败才发一次2500ms开机脉冲的启动逻辑，未增加自动RESET或循环开关机。
2. 使用CPIN确认SIM；连续两次明确无卡规则不变。每轮监测查询CSQ、CEREG、CGATT和CID 1激活状态。
3. CEREG仅1（本地注册）和5（漫游注册）进入数据准备。CSQ为0～31或99，99表示未知，不用信号值冒充连接健康。
4. 需要附着/激活时使用CGATT=1与CGACT=1,1，单条最多等待30秒，失败后至少间隔30秒重试；不发送CGACT=1激活全部CID，也不主动断开最后一条EPS承载。
5. 从CGPADDR=1取得有效IPv4、且显式配置的APN匹配，才置data_ready。客户端同时要求数据观测不超过20秒；SIM ready、注册、PDP ready与TCP连接分别报告。

APN在menuconfig的MODULE_MODEM_APN中配置，默认空串表示保留SIM订阅/模组现有CID 1配置。没有硬编码cmnet/cmiot，也没有根据运营商名称猜APN。显式配置APN时查询CGDCONT核对；CID 1未激活才尝试写入。若旧CID仍激活但APN不匹配，保持data_ready=0，不强行断开承载。专用卡的APN、鉴权、IPv6单栈需求需另行适配；本轮数据就绪要求IPv4。

AT监测和Socket操作共享一个UART任务，调用通过单请求队列串行执行。长时间的网络附着/激活可能推迟诊断请求，USB控制台和TTL任务仍独立运行；这里的AT等待上限不等于外层命令的端到端实时保证。

## TCP收发规则

固定使用socket 0、CID 1，一次一个连接：

| 环节 | 实现 |
|---|---|
| 建立前 | 先关闭残留连接，再查询MIPSTATE确认INITIAL/CLOSED；无法确认则报错 |
| 编码 | MIPCFG encoding设置发送/接收均HEX，避免00、CR/LF、OK或AT样式字节破坏行边界 |
| 模式 | MIPOPEN使用TCP流缓存模式2，配置autofree=1保留资源，显式关闭 |
| 连接结果 | 同时要求命令OK与MIPOPEN异步结果0；URC在OK之前/之后均处理，其他socket通知不能满足当前请求 |
| 发送 | 每次最多256字节，以HEX内联发送，检查MIPSEND返回长度和OK；它只证明模组接受数据，不证明业务执行 |
| 接收 | MIPRD按最多256字节读取，核对HEX字符数、声明长度和实际字节数；普通缓存查询不能冒充数据响应 |
| 断开 | 持续处理MIPURC，尝试读取保留的尾部缓存再报告EOF；真实固件行为待首板确认 |
| 超时/损坏 | 取消当前操作、排空异常输入、保留会话号隔离和连接隔离窗口；发送不明确时不自动重发 |

普通TCP的SSL开关在台架路径中显式关闭，测试仅发送用户输入的测试字节。正式云端接入必须先完成TLS与服务端身份校验；不能直接把明文台架接口用于发送生产凭据。AT协议没有事务ID，隔离窗口和状态回查降低迟到回复风险，但不能替代真实固件的边界时序测试。

## 应用新连接选路

uplink适配器在应用层选择Wi-Fi BSD Socket或ML307R AT Socket，没有创建PPP网卡或改变系统默认路由。

- auto模式优先尝试有IPv4的Wi-Fi。DNS/TCP连接失败且LTE数据就绪时，尝试同一端点的LTE连接。
- Wi-Fi连接失败后暂缓30秒重试；LTE待机期间到期后，由下一次新连接尝试Wi-Fi。频繁建立LTE连接不会无限延长这段窗口。
- 如果LTE不可用而Wi-Fi有IP，允许直接尝试Wi-Fi；两路均不可用则报错。
- wifi/lte模式用于指定链路验收，不自动换路。
- 打开的连接用token隔离，运行中的TCP不迁移；任何应用写入之后发生错误，都向上层报告，不到另一条链路重放。后续云端命令须另做持久去重与结果确认。

本版以实际调用产生的DNS/TCP结果作为当前端点的选路反馈，没有周期性访问某个公网站点。平台单点故障可能使两条连接都失败，但不会清除Wi-Fi配置或触发SmartConfig。默认无目标服务器，也没有自动TCP探测流量。

## 台架入口

控制台新增：

```text
net probe wifi <主机名或IPv4> <端口>
net probe lte <主机名或IPv4> <端口>
net probe auto <主机名或IPv4> <端口>
net echo wifi <主机名或IPv4> <端口> 00ACAC0D0A4F4B
net echo lte <主机名或IPv4> <端口> 00ACAC0D0A4F4B
net echo auto <主机名或IPv4> <端口> 00ACAC0D0A4F4B
```

probe只建立并关闭TCP；echo发送显式输入的十六进制，等待最多8秒级读取窗口并比较完整返回，失败不重试。外层等待还包含AT任务排队/单条事务时间。每次只运行一个后台诊断，期间可继续使用status；控制台最大行800字符，echo最多256字节。单连接不与后续正式业务并发争用。

电脑回显工具位于c5/tools/echo-server.py，使用已安装IDF Python即可：

```powershell
& 'D:/Espressif/python_env/idf5.5_py3.11_env/Scripts/python.exe' ./tools/echo-server.py --bind 127.0.0.1 --port 9000
```

默认回环地址用于电脑自身检查。Wi-Fi首板测试将bind改为电脑实际局域网IPv4，控制台填写同一地址，并允许台架端口通过电脑防火墙。4G测试须使用从蜂窝网络可达的自有服务器端点，普通电脑私网地址通常不能直接访问；不要把4G访问不了内网地址误判为固件故障。

status新增实际型号/固件、注册、CSQ、APN匹配、附着/PDP/IP/观测年龄、Socket会话及不明确发送计数，以及当前/最近成功应用链路和失败计数。0.4.0-dev起LTE绿灯表示新鲜PDP数据就绪，蓝灯仅用于真实MQTT会话；台架TCP成功不会点亮蓝灯。

## 首板验收（尚无通过记录）

| 场景 | 检查重点 |
|---|---|
| 实际ML307R-DL启动 | CGMM/CGMR、115200波特率、仅一次开机脉冲、型号不匹配保持诊断 |
| 无卡/锁卡/普通ERROR/弱信号/注册拒绝 | 不误报data_ready；保留原SmartConfig触发条件 |
| 订阅默认APN、显式APN、APN错误、CID已激活 | 状态和重试正确，不清空模组配置，不盲断最后承载 |
| Wi-Fi与蜂窝分别probe/echo | 确认实际路径；逐一验证00/AC AC/CR LF/OK及256字节边界 |
| Wi-Fi TCP不可达而LTE可达 | auto新连接走LTE，写入只发生一次 |
| Wi-Fi恢复 | 30秒后下一次新连接可回Wi-Fi，已有LTE连接不被强行迁移 |
| 两路指向同一故障平台 | 两路报错，不擦凭据、不自动配网、不重复业务控制 |
| MIPOPEN URC先于/晚于OK、延迟/重复/错误结果 | 不提前宣布连接成功，错误与隔离可诊断 |
| 服务端发送后立即断开 | 尾部缓存/EOF行为，不能静默丢失已返回数据 |
| UART溢出、模组重启、PDP掉线、迟到回复 | 旧会话拒绝，新连接先确认资源关闭；不重发不明确写入 |
| 同时持续TTL和10秒余时记录 | 无通用透传，主板状态与本地记录持续，不回写历史余时 |

完成上述实测后再冻结实际AT固件与量产超时参数。软件编译和共享解析器测试无法证明模组硬件、射频、运营商网络和AT固件真实时序已通过。
