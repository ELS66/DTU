# V0.14.4 物联网模块：已确认需求与后续集成项

日期：2026-10-20；当前依据：[物联网模块需求R4](iot-module-firmware-requirements-v0.14.4.md)。当前优先板内控制，MQTT后端接入按用户要求暂缓；不重复询问已确认选择。

## 1. 已确认需求

| 项目 | 用户决定 | 实施边界 |
|---|---|---|
| 产品 | 先做物联网模块，暂不做通用DTU | 通用Modbus/点位设计不作为当前前置 |
| 拓扑 | 一模块连接一台设备 | 无三口并行/多从站要求 |
| 接口 | TTL先跑通 | 协议1.8，3.3V、9600、8N1 |
| 网络 | Wi-Fi + 4G，Wi-Fi优先、4G备份 | 单一主业务会话，切换不重放设备控制 |
| 后端连接 | MQTT连接自有后端，文档稍后提供 | 当前暂缓后端接入，继续板内控制逻辑 |
| Wi-Fi/4G灯 | 绿灯网络就绪，蓝灯对应链路MQTT已连接；配网Wi-Fi橙灯闪烁 | MQTT未接入时正常自动显示蓝灯保持灭 |
| TX/RX灯 | 实际UART字节收发即亮，包含错误帧 | 对应现场主板串口，不是LTE内部AT流量 |
| Wi-Fi | 必须支持5GHz，保留2.4GHz | 5GHz须独立实测签收 |
| 设备相关数据 | 按不同设备类型的变长N字节处理 | 原样保留长度和内容，不要求参数表，不猜B1内部字段 |
| 配网方式 | SmartConfig | 首轮可用乐鑫Android测试App，之后集成小程序入口 |
| 开机触发 | 确认未插SIM且Wi-Fi不通，就进入配网 | 两条件同时成立；有卡但4G失败不自动当成无卡 |
| 用户引导 | 引导如何打开小程序进行配网 | 小程序入口、提示素材/载体和发送端作为集成工作 |
| 断电记录 | 每10秒记录剩余时间 | Flash周期快照；不依赖断电瞬间补写 |
| 重启行为 | 以主板恢复结果为准，模块只记录 | 查询主板更新当前状态，不从快照回写余时或主动续跑 |

原U01断电职责、U02/U03设备字段关注范围、U04网络优先级、U05开机配网条件与小程序方向均已处理，不再列为确认阻塞。18条Demo的外层长度/校验分析保留，内部参数不固定为Demo长度。

## 2. 开发自行细化并验证

- N字节载荷：按帧长计算N；外层指令/公共状态码和余时仍按协议处理，设备相关内容原样传递；补00、AC AC、多种长度和最大包长测试。
- 首次启动：并行尝试Wi-Fi和识别SIM，定义检测窗口、健康检查与重试。SIM状态未知/AT超时/锁卡不能当作未插卡；平台服务单点故障不能直接导致清空Wi-Fi。
- 配网：SmartConfig与小程序发送端的具体协议类型/版本、Android/iPhone权限、5GHz支持与成功确认；首轮官方App仅验证固件台架，不代表小程序链路已完成。
- 引导：现有模块仅有LED；小程序入口码、标签/说明、页面或主板已有显示能力的实际组合在集成中落实，不假称板上能够显示文字。
- 配网失败/超时：保留上一有效凭据、出厂身份、设备编码和运行记录；回到重试/等待状态，具体窗口依据实测固定。
- 10秒Flash快照、串口异步事件、云端去重、网络切换和OTA并发稳定性。

## 3. 后续业务集成资料

这些项目在进入相应任务时补齐，不阻塞当前TTL解析、N字节往返、网络状态机和10秒记录开发：

| 项目 | 所需资料/决定 |
|---|---|
| 小程序对接 | 实际小程序名称/AppID或既有工程、打开方式、引导素材；后续小程序发送端开发与联调 |
| 云端接入 | MQTT方案已确定；地址、身份认证、主题、业务消息与状态/事件同步契约等用户后续文档，当前暂缓 |
| 编码与二维码 | 6字节设备编码分配、业务二维码内容与激活来源；不从设备类型推导单台唯一ID |
| SIM与升级 | 实际卡/APN、流量策略、是否允许4G OTA及工作中升级窗口 |
| 项目验收 | 首块实物/目标主板可用时间与首个演示目标 |

协议内部参数语义由设备/业务端按机型管理；模块不以要求补齐参数表或改主板协议作为开工条件。
