# C5 0.5.0-dev：主板通信与快照健康

日期：2026-10-20。硬件V0.14.4，ESP-IDF 5.5.1。MQTT后端接入继续等待用户文档，本轮只补板内逻辑。

## 主板通信与运行状态分开判断

| 诊断 | 状态 | 判断依据 |
|---|---|---|
| BOARD_CONTACT | not_started / waiting / online / offline | 已通过现有语义检查的匹配回复，或合法C系列面板事件；原始字节和错误协议帧不能刷新在线状态 |
| BOARD_STATE | unknown / fresh / stale | 最近一次已接受的B2成功状态、A2～A4时间回复或C1～C4运行事件 |

例如B2返回“不支持”、而B1仍有匹配回复时，通信可显示online，运行状态仍可能unknown/stale。只有C5参数事件时，也不能据此更新剩余时间。旧的、无在途请求匹配的回复只计入unsolicited，不作为本轮接触证明。

默认参数：

- 运行状态过期阈值为max（配置5000ms，3次轮询间隔＋回复超时），默认5000ms。
- 通信失联阈值再覆盖一帧最大4096字节在9600、8N1下约4267ms的线上时间，即max（状态阈值，3次轮询间隔＋回复超时＋4267ms），默认7767ms。
- menuconfig的MODULE_BOARD_STALE_MS可调整基础阈值；放慢B2轮询时，实际阈值同步扩展。默认B2仍每1秒查询，快照周期仍为10秒。

没有接受过主板帧时先显示waiting，到失联阈值后显示offline。首次超时只累计一次失联；收到合法帧后累计一次恢复。连续请求超时只由匹配回复清零，主动面板事件能证明通信在线，但不会掩盖请求未被回答。FIFO溢出取消的在途请求另计aborted，不冒充主板应答超时。

状态过期会保留last_state、last_remaining和观测年龄作为最后观测，不能当作当前运行事实。不将过期变为“设备停止”，不自行递减或归零余时，不自动发送A1/A4等恢复控制。收到新状态后以主板为准更新。指示灯规则仍按[板内控制清单](c5-board-control-requirements-v0.14.4.md)，不会把设备失联混入Wi-Fi/4G网络灯含义。

## 快照调度与写入节流

| 情况 | 调度规则 |
|---|---|
| 本次启动第一条有效观测 | 250ms合并窗口后保存最新值 |
| 正常新鲜B2观测持续到来 | 距上次成功写入10秒后保存最新观测 |
| 启动/暂停/继续/停止/结束等关键变化 | 250ms合并，距上次成功写入至少2秒；保存合并窗口内的最新状态 |
| 完全相同的重复面板事件 | 刷新观测时间，累计duplicate_event；不反复产生额外关键写入 |
| 连续不同的关键变化 | 合并为最新快照，累计merged_change；连续事件不无限延长合并窗口 |
| 观测过期或没有新观测 | 不把旧值重新打上新时间，不重复写旧快照；过期时等待主板重新同步 |
| Flash写入/提交失败 | RAM提交位置不前进，保留最后成功记录；5秒后用最新有效观测重试 |
| 记录序号用尽 | 标记sequence_exhausted，停止新增记录并保留历史 |

10秒是正常情况下的写入调度间隔；NVS/Flash操作和任务调度耗时仍须实板测量，不能据此承诺最后记录精确对应掉电前10秒。关键变化可能使记录更密集，2秒最短间隔用于限制事件风暴时的额外写入；不是仅写一次/10秒的硬上限。

快照是最新状态的周期记录，不是完整的面板事件流水。合并可能省略很短暂的中间状态；完整事件持久化/上报仍是后续工作。不同C命令来源仍保留在选中的快照中，C4返回非零余时不会被清零。正常轮询即使状态/余时不变，也因观测时刻更新而按10秒周期记录。

写入开始时复制观测及revision，Flash操作期间不占用状态锁。写入中又收到新观测时，旧副本提交成功只推进到该副本的revision，新的变化仍待处理；失败不会把任何变化标为已提交。保存的观察时间来自主板数据被接受时，提交完成时间另外用于诊断。

## 存储状态

仍使用原有runtime分区、双槽record0/record1与36字节C5RS版本1/CRC格式，分区和记录布局没有改变，不要求清空旧记录。

| STORAGE | 含义 |
|---|---|
| starting | 尚未进行初始化 |
| unavailable | 分区/句柄/存储任务初始化失败；TTL和内存观测继续可用 |
| read_degraded | 启动读到损坏记录槽、且本次启动还未成功写入新记录 |
| ready | 可记录，最近写入无错误；启动损坏槽数量仍保留作诊断 |
| write_error | 最近写入或提交失败，等待退避重试 |
| sequence_exhausted | 序号溢出保护，保留历史，停止新增记录 |

不存在的记录槽视为首次使用，不算损坏。损坏CRC、长度或读取异常的槽计入invalid_boot_slots，仍优先选择其他完整有效槽的最高序号。没有可用历史时保持HISTORY none，但明确报告损坏/初始化信息，不自动擦除NVS。

保存失败时不更新RAM中的最后提交记录，也不擦除历史；实际Flash掉电原子性和NVS错误行为仍须故障注入验证，软件检查不替代真机证明。

## status输出

沿用status命令，新增：

- BOARD_STATE：unknown/fresh/stale、最后状态/余时、观测年龄、实际过期阈值。
- BOARD_CONTACT：通信阶段、连续请求超时、失联/恢复次数、因本地溢出取消请求数、最近合法帧年龄、实际失联阈值。
- STORAGE：可用性、初始化错误、最近写入错误、成功/失败数、启动损坏槽数、是否已有本次启动提交。
- SNAPSHOT：pending、blocked_stale、lagging、距最近成功提交的时间、最近尝试/成功时刻、下次重试时刻、保存原因、重复事件/合并变化/拒绝观测数。

保存原因值为0=none、1=first、2=critical、3=periodic。所有运行时刻均为本次ESP启动后的单调毫秒，不是日历时间。跨启动的HISTORY仍显示原boot标签与观测时刻，不把它与本次uptime直接相减。

pending表示有尚未成功提交的新revision。blocked_stale表示待写观测已经过期。lagging表示存储可用、观测新鲜且仍有待提交内容，但自本次首观测/最近成功提交已超过15秒；该阈值为当前诊断参数，不触发擦除、复位或设备控制。

## 软件验证与首板验收

共享生产C核心共9227项检查通过，新增覆盖：

- 新鲜度边界、未知观测、单调时间回退、非法状态及revision溢出拒绝。
- 初次写入、正常10秒节奏、重复事件、20秒高频状态事件、250ms合并不被连续事件饿死、2秒写入间隔。
- 写入中状态更新、不可变捕获副本、失败退避、成功位置不超前、写入失败后用新值重试、过期数据不重写。
- 首次没有回复、失联只计一次、恢复、事件与回复对连续超时的区别、饱和计数器、最大帧时间预算。

这些是实际被固件调用的策略函数与原有协议/记录/灯/网络检查。NVS初始化/提交API错误、真实Flash突然断电和调度抖动尚未做实物故障注入，不记为已通过。

首板至少验证：

1. 无主板启动：先waiting，随后offline；运行状态unknown，不产生伪造快照。
2. 正常B2查询后拔线：状态变stale、通信随后offline；保留最后观测与历史，不自动启停。
3. 只返回错误状态码或只发C5：通信可online，运行状态不能虚假fresh。
4. 恢复串口：只计一次恢复，查询主板新值，不从历史恢复余时。
5. 重复/高频面板事件：应答持续，验证真实写入频率和最新快照；明确中间状态不是完整事件日志。
6. NVS空间/写入故障及修复：错误、退避、恢复状态准确，原历史不被主动擦除。
7. 写入过程中突然断电：重启选择完整记录，主板仍为当前状态权威。
8. 长N字节帧、Flash操作与网络配网并发：通信阈值/状态年龄可解释，不把未测时序宣称已验收。
