# 架构决策记录

## ADR-015：本地诊断采用固定RAM事件环，首板以独立主板模拟器联调

日期：2026-10-20。状态：0.7.0-dev共享核心24491项、模拟器25项自测与C5编译完成，尚无实物通过记录。

将主板/存储/网络/串口/任务故障与状态变化写入64条RAM环，只保存数值字段，分页报告覆盖缺口，不逐条写普通轮询和倒计时、不增加Flash写入。环在重启后清空，上次看门狗上下文仍只依赖已有RTC机制；它不是可靠业务事件队列或跨断电审计日志。

电脑工具独立模拟协议1.8主板、N字节参数和故障回复，显式选择USB转TTL COM，不自动操作ESP控制台。工具自测对照原18条Demo，不将内存/虚拟时钟检查称为串口驱动或电气验收。详见[本地诊断与首板模拟器](c5-local-diagnostics-and-bench.md)。

## ADR-014：按任务推进喂狗，串口错误保守恢复，原始参数先作RAM观测

日期：2026-10-20。状态：0.6.0-dev源码、23380项共享核心检查与C5编译完成，待实板故障注入。

独立监督器检查现场串口/记录/灯/网络/4G的推进预算，4G只在有界事务结束或空闲轮结束后更新；不在接收pump中喂进度。故障锁存后停止TWDT用户喂狗，由5秒panic复位保护处理，RTC保留一次故障上下文，未启用的失败组件明确显示停用。业务断网/无主板不等于任务卡死。

UART硬件错误或观察到事件队列满时丢弃不可信接收、取消在途、排空保护，不重放控制命令；压力为采样而非SDK精确丢事件计数。B1/B3长回复线速纳入等待预算。B1/B3/C5按原始N字节建立带CRC/revision的互斥RAM快照，新C5优先于旧B3；不解释机型字段、不以RAM ACK代替持久化/云端ACK，重启重新查询，不自动回写参数。具体边界与首板用例见[任务/UART/缓存说明](c5-task-uart-cache.md)。

## ADR-013：主板接触与运行观测分离，快照按新鲜度合并提交

日期：2026-10-20。状态：0.5.0-dev源码及共享策略测试完成，C5编译通过，待首板验证。

主板合法匹配回复/事件维护通信接触；只有已接受的运行状态数据刷新观测。通信online不代表运行状态fresh，失联/过期均不触发设备控制。状态默认5秒过期，接触超时另覆盖最大4096字节帧在9600波特率的时间，默认7.767秒；配置放慢轮询时同步扩展。

快照保持正常10秒周期，关键变化250ms合并、成功提交间隔至少2秒；重复事件不制造额外关键写入，写入中变化按revision继续保留，失败5秒后用新鲜最新值重试。历史记录、分区和36字节C5RS格式不变，不擦NVS、不从历史恢复主板余时。NVS初始化/读取/写入、序号保护和落后诊断分开报告。当前不把最新快照视为完整事件日志，实际掉电/NVS故障仍待实测，详见[运行健康说明](c5-runtime-health.md)。

## ADR-012：MQTT方案已定，当前先做板内控制和统一指示灯

日期：2026-10-20。状态：用户明确确认，实施依据为[需求R4](iot-module-firmware-requirements-v0.14.4.md)。

模块通过MQTT连接自有后端；文档正在整理，本轮暂缓后端接入，继续板内控制。用户确认两组绿灯表示网络就绪、蓝灯表示对应链路MQTT已连接，SmartConfig用Wi-Fi橙灯闪烁；TX/RX按现场UART字节活动触发，包含协议错误帧。TCP台架连接不作为MQTT蓝灯依据。

0.4.0-dev将LED输出统一到独立任务，补齐状态节奏、过期保护、长帧TX/解析前RX、2秒逐灯测试和5秒临时覆盖。MQTT客户端尚未接入，正常蓝灯保持灭。板内待办按主板新鲜度/失联、快照健康/节流、关键任务监督、UART异常和原始参数缓存排序，详情见[板内控制清单](c5-board-control-requirements-v0.14.4.md)。

## ADR-011：ML307R台架采用缓存HEX TCP，应用层选择新连接链路

日期：2026-10-20。状态：0.3.0-dev已交叉编译，实板待验证。

工作区ML307资料包的通用AT V2.0.5和TCP/IP V5.1.5明确覆盖R-DL；C专用拨号文档不作为本板UART PPP依据。当前选择AT TCP流缓存模式、双向HEX、256字节分块和唯一UART任务，区分命令OK与异步连接结果，用会话号隔离旧调用，不自动重放不明确的应用写入。读取型号/固件、注册/CSQ、附着、CID 1和IPv4，不猜APN、不自动断开最后承载。

应用适配器在新连接时优先Wi-Fi，连接失败且LTE可用时尝试LTE；30秒后允许新连接重试Wi-Fi。已有连接不跨链路迁移，未增加PPP网卡或系统默认路由切换。当前普通TCP仅用于显式端点的probe/echo台架验证，生产TLS/云端认证与周期性健康探测仍待实现。详见[4G联调说明](c5-lte-bringup.md)。

## ADR-010：联网台架里程碑与配置验证边界

日期：2026-10-20。状态：0.2.0-dev已实现并交叉编译，实板待验证；下列时间均为开发参数，不是新增用户承诺。

在TTL/余时记录任务之外启动Wi-Fi和ML307R AT任务。Wi-Fi采用2.4/5GHz自动选择；45秒开机窗口结束，仅两次明确缺卡且Wi-Fi无IPv4才启动一次180秒ESPTouch/v1，未知/锁卡不作为缺卡，运行中掉线不扩展自动配网。初始Wi-Fi成功也立即关闭本次自动判定。新配置只在RAM试连，确认目标AP关联且取得IPv4后保存；失败恢复原配置，不擦NVS。Wi-Fi IPv4与SIM READY均不代表业务在线，4G数据/实际选路/互联网健康/云端另行实现和验收。

首轮Android App使用明确支持C5 5GHz的ESPTouch 2.3.2或更新版；正式小程序入口和二维码仍待集成。AT先探测已开机模组，无应答才按硬件手册发一次2500ms开机脉冲，不循环复位。详见[网络联调说明](c5-network-bringup.md)与[开发进度](c5-firmware-progress.md)。

## ADR-009：设备相关数据原样传递，固定开机配网条件

日期：2026-10-20。状态：用户已确认，当前实施以[模块需求R3](iot-module-firmware-requirements-v0.14.4.md)为准。

设备相关内容按不同设备类型的变长N字节处理，模块负责外层消息、公共状态码、长度和校验，原样保留内部数据；B1布局差异和机型参数表不再作为开发前置。网络确定为Wi-Fi优先、4G备份。开机确认未插SIM且Wi-Fi不可用时进入SmartConfig，并引导用户打开小程序配网；首轮官方Android测试App的台架验证安排保留。SIM未知、锁卡、注册失败不等于未插卡，运行中掉线不擅自扩展开机触发条件。

原ADR-008中“B1/参数仍需补齐”仅保留历史背景，不作为当前模块实现要求。每10秒余时记录、主板恢复结果为准的职责不变。

## ADR-008：本轮先做设备专用物联网模块

日期：2026-10-20。状态：产品范围、断电记录责任与首轮配网端已确认，协议细节待补。

用户确认Wi-Fi+4G、一模块一设备、TTL优先、必须支持5GHz Wi-Fi、SmartConfig配网，暂用《联网模块_串口协议1.8》，每10秒保存剩余时间。用户补充确认：断电后以主板恢复结果为准，模块只记录，不从本地快照回写余时或自动续跑；首轮用乐鑫Android测试App，跑通后再集成自己的入口。通用DTU/Modbus/点位方案暂不实施为本轮首发要求。已保存用户协议原件副本，18条Demo的候选长度与累加和均核算一致；B1正文与Demo冲突，主板参数仍需补齐。

当前依据：[模块需求R3](iot-module-firmware-requirements-v0.14.4.md)、[协议分析](iot-module-uart-protocol-v1.8-review.md)、[确认记录](esp32-firmware-confirmations-v0.14.4.md)。旧代码与协议草案保留，云端模块接口后续单独冻结。

## ADR-007：V0.14.4固件硬件基线切换为ESP32-C5

日期：2026-10-20。状态：硬件事实已核对；产品范围待确认。

本次采购主控ESP32-C5-WROOM-1U-N8R8、蜂窝ML307R-DL；固件目标改为esp32c5，旧S3参数不再直接沿用。三个现场接口共享FIELD_TX/FIELD_RX，仅支持一次连接一组；TTL TX经电阻直接来自3.3V GPIO，当前PCB无SW位号。网络首版是否包含4G、配网方式、采样与缓存目标仍由用户确认。

具体需求、GPIO映射、分期与验收见[固件需求说明书](esp32-firmware-requirements-v0.14.4.md)和[待确认清单](esp32-firmware-confirmations-v0.14.4.md)。下方ADR-004的“电路未定”属于旧状态；其中物理接口与协议分离的原则继续适用。

## ADR-001：首版一对一，模型分离网关与现场设备

状态：已采纳。网关有硬件身份、连接、配置与固件；现场设备有产品、数据点、历史与业务归属。首版数据库限制一个网关至多一个活动绑定；未来可以通过迁移放开限制。

## ADR-002：数据和命令绑定配置版本

状态：已采纳。配置发布产生不可变快照；遥测携带 configRevision；命令携带 expected configRevision。设备尚未应用目标版本时拒绝执行。服务端用采集时版本解释补传数据。

## ADR-003：控制结果区分写响应与回读确认

状态：已采纳。写响应仅表示底层设备接受写请求；回读符合预期才确认最终状态。超时为结果未知，不自动重试可能产生副作用的动作。

## ADR-004：物理接口与协议分开

状态：待硬件验证。RS485、RS232、TTL 是接口；首版协议暂按 Modbus RTU。三接口电气设计、是否同时运行、模组 Flash 大小和实际目标设备寄存器表仍未确定。

## ADR-005：协议先冻结逻辑字段，字节布局由测试向量确认

状态：进行中。首批实现遥测帧、配置及命令的 v1 契约。消息认证依赖 TLS 与逐网关凭据，应用层用 bootId + sequence 去重。线上结构发布后不原位更改，新增版本号。

## ADR-006：后端改用 Node.js + TypeScript

状态：已采纳。用户已部署过宝塔 Node 项目，2026-09-28 明确选择从 Java 切换。后端以 Fastify 模块化单体实现，前后端可共享 TypeScript 类型；保留 PostgreSQL SQL 迁移和原领域模型。遥测/控制流程须避免阻塞事件循环，容量以实测为准。生产建议 Node.js 24 LTS。
