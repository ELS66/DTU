# ESP32-C5 / V0.14.4 硬件与固件验证清单

更新：2026-10-20。用户已反馈PCB到货，开始准备焊接；软件暂留0.7.0-dev。装配步骤见[焊接/限流上电检查](v0.14.4-assembly-checklist.md)。文件核对完成不代表实物通过，来料替换和电源/焊点均待首板验收。当前先做物联网模块，范围见[需求R4](iot-module-firmware-requirements-v0.14.4.md)，已确认项和剩余问题见[确认记录](esp32-firmware-confirmations-v0.14.4.md)。

| 项目 | 当前事实/状态 | 验证方式 |
|---|---|---|
| 主控 | 本次采购ESP32-C5-WROOM-1U-N8R8；旧软件计划中的S3已过时 | C5构建、USB刷写、读出实际Flash/PSRAM容量；按8MB/8MB规划 |
| 蜂窝 | 本次装配ML307R-DL；用户已确认本版Wi-Fi+4G | 到货AT固件、无硬件流控收发、TLS/业务消息/OTA；无卡和弱网恢复 |
| Wi-Fi | 5GHz与SmartConfig源码已接入，尚未实板验证 | 使用支持C5 5GHz的手机发送端；5GHz配网/联网/重连必须真机验收，保留2.4GHz能力 |
| 现场串口 | GPIO23 TX / GPIO24 RX；三个接口共用一路 | 三口分别连接测试从站，不能同时接入 |
| TTL | 首批优先；协议1.8明确3.3V/9600/8N1；TX为GPIO23经R35，RX经R36/U12 | 与目标主板交叉接线、共地，实测电平和16类指令；旧5V说明不再作为依据 |
| RS232 | BL13232ETS，连接共享UART；本轮TTL优先 | 后续核验接线、电气电平与接口适配，不作为当前TTL业务闭环前置 |
| RS485 | 本次采购SP3485EN-L/TR；GPIO3同时控制DE和/RE | 启动DE低、末停止位后转接收、偏置/可选终端与长线通信；不把共地收发器当隔离接口 |
| 三口并行/自动选口 | 当前电路没有三路独立UART、接收屏蔽或接口检测 | 产品限定一次接一组；软件配置不能提供电气隔离 |
| 本地按键 | 当前104个PCB器件无SW位号；J6/J7保留治具孔 | 开机无SIM且Wi-Fi不可用进入SmartConfig并引导小程序；不得沿用SW2/SW3/SW4描述 |
| LED/日志 | 8灯均由ESP控制，低亮；D30/D33橙色；GPIO11/12为现场TX/RX。统一管理已实现，绿灯网络、蓝灯MQTT、配网橙闪，字节活动含错误帧 | USB日志、2秒逐灯测试、5秒临时覆盖、长帧持续时间、启动复用与安全初值；尚未实测 |
| LTE控制 | GPIO6/8经Q1反相驱动PWRKEY/RESET；没有独立VBAT断电开关 | 测实际极性/时序，验证ESP单独复位后的模组状态恢复 |
| LTE状态/卡检测 | STATE/NETLIGHT未接ESP，不能按旧稿做GPIO检测 | AT/URC与超时判定；不承诺SIM热插拔 |
| 电源 | 本次SCT2330TVBR降压、TLV75901PDRVR；P脚均为VIN_IN | 首板限流上电，LTE峰值负载、纹波、启动和温升；J6 EN不得接5V |
| OTA与运行快照 | 8MB Flash双槽预算；用户要求每10秒保存剩余时间；无后备RTC | 原子Flash日志、磨损/新鲜度、断电恢复与OTA并发；不沿用2MiB全量遥测历史预算 |
| 现场设备 | 串口协议1.8；设备相关内容按变长N字节处理，不按Modbus接入 | 不同N长度原样往返；不要求机型参数表；断电后当前状态跟随主板，模块只记录 |

连接依据为定版导出工程与PCB保存重开快照，见[可核对的硬件映射](esp32-v0.14.4-hardware-map.json)。历史硬件说明仅用于追溯。
