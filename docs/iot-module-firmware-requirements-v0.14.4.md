# V0.14.4 物联网模块 ESP32 软件需求说明书

日期：2026-10-20；版本：R4；状态：已确认MQTT及灯语义；后端接入按用户要求暂缓，当前优先板内控制逻辑。

当前产品为**连接一台设备控制主板的物联网模块**。硬件沿用V0.14.4，第一阶段通过TTL和用户提供的串口协议1.8控制设备、同步状态、处理计时和二维码。原通用DTU、Modbus寄存器映射、通用点位采集方案不作为这版首发需求。

本文取代[原DTU固件需求R1](esp32-firmware-requirements-v0.14.4.md)作为当前软件入口；原R1仅保留硬件追溯和后续通用DTU参考。[协议分析](iot-module-uart-protocol-v1.8-review.md)与[确认清单](esp32-firmware-confirmations-v0.14.4.md)共同组成当前需求。

## 1. 已确认范围与待决边界

| 项目 | 本轮决定 | 尚未确认的细节 |
|---|---|---|
| 产品定位 | 设备物联网模块，暂不做通用DTU | 是否需要同步调整平台界面/模型另行安排 |
| 网络 | Wi-Fi + 4G；Wi-Fi优先、4G备份 | 切换时间、防抖和4G流量/OTA策略 |
| 后端协议 | MQTT连接自有后端；文档正在整理，本轮暂缓接入 | 服务器、认证、主题/载荷、应用ACK等由后续文档冻结 |
| 指示灯 | 绿灯网络就绪、蓝灯对应链路MQTT已连接；配网用Wi-Fi橙灯闪烁 | 节奏与验收见[板内控制清单](c5-board-control-requirements-v0.14.4.md) |
| TX/RX | 按现场UART字节活动点亮，包含错误帧 | GPIO电平、长帧持续时间与连续活动需实板验证 |
| Wi-Fi | 必须支持5GHz；保留2.4GHz能力 | 手机/路由器兼容矩阵与验收信道 |
| 设备拓扑 | 一模块接一台设备 | 无多从站、三口并行要求 |
| 首批接口 | TTL优先跑通 | RS485/RS232本轮仅保留硬件与诊断适配，不作为主线先行验收 |
| 配网 | 开机确认未插SIM且Wi-Fi不可用时进入SmartConfig，并引导打开小程序；首轮可用乐鑫Android测试App | 配网检测窗口、引导载体、小程序发送端集成与超时策略 |
| 设备协议 | 使用串口协议1.8；设备相关内容按变长N字节原样处理 | N从有效帧长度得到，内容语义由对应设备/业务端处理，不要求先补参数表 |
| 断电记录 | 剩余时间每10秒记录一次；断电后以设备主板恢复结果为准，模块只记录 | 记录新鲜度、异常诊断和主板实际恢复行为测试 |

网络优先级和开机配网触发已经确认。“每10秒记录”不代表每10秒云端上报，也不代表要求保存每10秒的完整历史数据。

## 2. 硬件和接口基线

- 主控：本次采购ESP32-C5-WROOM-1U-N8R8，按8MB Flash/8MB PSRAM规划；蜂窝：ML307R-DL。
- 现场TTL：3.3V逻辑、9600、8N1；ESP GPIO23发送、GPIO24接收，对接J3。RS485 DE GPIO3在TTL模式始终置低。
- LTE UART：GPIO0发送、GPIO1接收；GPIO6/8分别经Q1反相触发模组端低有效开关机/复位。当前无RTS/CTS接线。
- 下载和日志：GPIO13/14 USB Serial/JTAG；GPIO11/12已作活动灯，不能输出默认UART日志污染现场或LTE串口。
- J3的P接VIN_IN是模块主电源输入，不是3.3V/5V外设供电输出；TTL接线须共地，主板能否给模块供电需按电源要求核实。
- 当前无板载按键，J6有EN/BOOT治具孔；BOOT是GPIO28。SmartConfig不能直接套用“长按板载键”流程。
- 没有独立LTE VBAT断电开关、后备RTC或已验证的掉电预告中断；剩余时间靠运行期间周期落盘，不依赖突然掉电后的最后一次写入。

完整GPIO与网表证据见[硬件映射](esp32-v0.14.4-hardware-map.json)、[硬件验证清单](hardware-support-matrix.md)。TTL电平与串口参数已经由协议文档确定，电气质量和实际供电仍须首板验证。

## 3. 模块与设备主板的职责

```text
手机/业务平台 ⇄ Wi-Fi(2.4/5GHz) 或 4G ⇄ ESP32模块 ⇄ TTL协议1.8 ⇄ 设备控制主板
```

主板执行设备启停、计时、面板操作及实际控制。模块负责网络、云端指令转发与结果跟踪、状态/事件同步、剩余时间恢复快照、配网、身份/二维码同步和自身OTA。

用户已确认主板恢复结果为准，模块只记录。以主板B2查询与C系列事件作为实际工作状态来源，ESP保存其最后有效状态。模块可用单调时钟平滑显示倒计时，但预测值与主板确认值分开，不能用预测代替执行事实。模块不会为了恢复余时发送A1/A4，也不根据本地快照自行扣除停电时间。

## 4. 功能需求与验收

### M01 启动与设备握手

1. 初始化安全GPIO、USB日志、实际内存与分区；读取出厂身份、网络配置和最近有效运行快照。
2. 无网络也启动TTL接收和主板事件应答；不得为等待联网或SmartConfig阻塞设备通信。
3. B1/B3及设备相关回复按公共状态码+变长原始数据保存和同步，不根据Demo猜测固定设备类型/参数布局；机型标识如业务需要可由出厂配置/云端绑定提供，B1内部布局不作为启动前置。B2的明确公共状态/余时字段仍按协议解码。
4. 缓存存在未完成任务时先与主板核对，不自动发送A1。主板保持原任务、主板已重启或串口无响应分别处理。
5. 上电、重连、OTA重启不能自动重放旧业务启动命令；先标记“待核对”，主板查询成功后跟随其实际状态。主板未回复时只显示带时间/过期标记的历史记录，不自动变成待启动任务。

验收：无卡/无网/无配置/主板未响应均可进入可维护状态；仅ESP重启不重复启动已运行主板。

### M02 TTL字节流与协议适配

- 按[协议分析](iot-module-uart-protocol-v1.8-review.md)实现AC AC帧解析、长度边界、累加和、基础值解码、半包/连包/重同步；候选线格式须经协议方确认。
- 首版16条指令按需分里程碑实现：A1～A4启停暂停继续，B1～B5类型/状态/参数/时间，C1～C7主板事件和二维码交互。
- 一次最多一个模块发起的在途请求；同时接收主板主动事件，按方向和数据形状分发，应答不等云端返回。
- 建议查询超时500ms、最多一次读重试作为台架初值；变更状态指令不自动重发。真实时延与静默窗口按主板测定。
- B1/B3/B4/C5的设备相关内容按变长N字节处理，N从合法帧长度取得，不固定为某款Demo的长度，不解读具体参数含义，不要求先提供设备参数表。保留指令方向、公共状态码、实际字节数和原始内容；已知的启停、余时、时间等公共字段保持既有解析。
- 云端传输变长内容时建议使用明确标记的Base64加实际字节数；串口端始终还原原始二进制，保留00、AC AC等任意内容。只开放已支持指令的受控数据载荷，不开放任意UART隧道。长度上限、校验、缓冲和超时仍由模块检查。
- 不要求Modbus功能码、寄存器/Slave配置、20/128点通用采集；旧点位与二进制遥测契约不直接套到本协议。

验收：18条现有Demo全部解析一致，补充错长度/错校验、未知状态、主动事件穿插和迟到回复。Demo验证已完成文件计算，C实现和真机验证尚未完成。

### M03 设备运行和云端控制

- 支持带秒数启动A1、停止A2、暂停A3、继续候选A4、B2状态查询。A4精确定义、重复A1行为及允许时长范围须协议方确认。
- 云端指令至少具有commandId、模块身份、任务/运行会话标识、操作、参数、截止时间；模块记录执行阶段，重复commandId不再向主板发送同一控制。
- 区分云端收到/模块收到/串口已发送/主板回复成功/状态查询一致。A1仅有成功码，不单凭该码伪造主板剩余时间，随后B2核查。
- 由于串口协议没有事务ID，发生写后失联/掉电时记录结果不确定，禁止根据网络重发次数盲目追加运行时间。B2只能证明当前状态，不能独自证明某一历史命令执行过。
- 云端暂离线时主板继续按自己的运行逻辑工作；面板操作仍可由C系列事件同步至模块。联网恢复后先同步现状和待处理结果，不执行过期指令。
- 运行会话标识是模块/云端待设计的元数据，不是假称串口协议已有任务ID；设备或模块更换/复位后的关联需明确。

验收：启动、暂停、继续、停止闭环；重复云端命令、丢回复、设备面板操作和网络切换不会被错误当成新任务重复启动。

### M04 每10秒剩余时间快照与断电恢复

**已确认：剩余时间每10秒记录一次；断电后以主板恢复结果为准，模块只记录。** 持久介质使用Flash；PSRAM不能用于掉电保存。快照用于保留上次观测、诊断和云端同步，不是主板计时恢复输入。

- 运行期间按10秒周期提交运行快照；建议B2每1秒刷新内存状态，持久化时检查数据新鲜度。1秒查询仍为技术建议，不能把串口陈旧值宣称为误差不超过10秒的精确记录。
- 快照候选字段：格式版本、递增记录序号、模块身份、设备类型/编码、运行会话标识、工作状态、主板确认剩余秒数、观察时刻与可信度、最后控制阶段、校验/提交标记。
- 建议在启动/暂停/继续/停止/结束等已确认状态变化后及时另存快照，避免10秒旧记录覆盖新状态；这是对10秒周期的补充建议。主板手动停止C4带非零剩余时间时，不能未经业务确认清零。
- 采用追加日志/轮换扇区、完整性校验和原子提交；启动扫描选择最后完整有效记录，写一半的记录不覆盖上一条。周期任务和事件提交经同一写入队列按状态版本排序。
- 若持续每10秒写一次，上限8640次/日；只在状态有效且内容需更新时写，结合磨损均衡与介质参数验证寿命，不能固定单扇区反复擦写。
- 突然断电不保证最后一次额外写成功；没有独立RTC和后备电源，不自行扣除断电时长。历史快照可能比断电瞬间实际剩余时间多，差异包含周期、主板值新鲜度和提交延迟；恢复联网后不能用这个旧值覆盖主板当前值。
- 重启流程：读有效快照作为历史记录→查询主板现状→按主板结果更新当前状态/余时→记录差异并同步云端。主板仍运行则跟随运行，主板空闲则显示空闲；快照有余时也不得回写、追加时长或自动启动。
- 当前没有只恢复剩余时间而不启动的指令，但本版已确认只记录，因此不要求新增这类指令。主板掉电后若自行恢复为0，模块以0为当前值，并保留先前记录用于诊断，不自行补回旧余时。
- 计时结束C1、手动停止C4、暂停C3和主板复位不得混为同一个“余时归零”事件；任务身份不明时记录关联待核对标记，当前运行状态仍以主板为准。

验收：连续记录间隔、写入中断电、旧/新记录交替、模块单独复位、主板单独复位、整机掉电、剩余时间临近0和主板状态冲突。验收必须明确记录值误差和是否发生非预期启动。

本版先保障运行恢复快照；全量离线遥测历史、多小时点位缓存不是已确认需求，不继续套用R1的2MiB遥测缓存预算。

### M05 Wi-Fi、5GHz与SmartConfig

- 本版必须验收5GHz Wi-Fi联网，不能仅用2.4GHz成功代替。保留双频STA能力，信道与路由器认证方式按照实际使用环境确认。
- 配网方式采用SmartConfig；开机在检测窗口内确认“未插SIM”且“Wi-Fi不可用”时进入配网。这里是两个条件同时成立，不是任一网络失败就配网；已保存Wi-Fi凭据也须先尝试连接，不能因存在旧配置而跳过判定。
- SIM状态区分ABSENT、PRESENT、LOCKED与UNKNOWN/模组未就绪；通过ML307R实际AT/URC确认，不能把AT超时、PIN锁卡、欠费或注册失败当作未插卡。Wi-Fi连接/IP/基础网络健康与云端服务状态分别检测；平台单点故障不应直接引发清配置和配网。检测窗口与基础网络检查由开发给出实测参数。
- 已插SIM且Wi-Fi不可用时尝试4G，4G失败进入诊断和有界重试；用户本轮没有要求把“有卡但4G不可用”扩展为自动配网。运行中掉线也不自动套用开机配网触发规则。
- 配网时提示用户如何打开小程序并开始配网，产品入口确定为小程序。小程序标识/入口码和提示载体通过配置集成；现有板仅有LED，不能假称ESP能显示文字。提示可由配套说明/标签、小程序页面或设备主板已有显示能力承载，具体呈现是后续集成项，不阻塞TTL和配网状态机。
- 首轮仍按已确认安排使用乐鑫Android测试App验证固件与5GHz；小程序阶段需单独实现并验证与固件一致的SmartConfig发送、手机权限、5GHz兼容和成功确认。ESPTouch/v2类型由发送端兼容验证决定，不将官方App成功当作小程序链路已完成。
- 乐鑫[ESP32-C5 SmartConfig文档](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c5/api-reference/network/esp_smartconfig.html)列出ESPTouch/v2支持；[Android App v2.3.2发布记录](https://github.com/EspressifApp/EsptouchForAndroid/releases/tag/v2.3.2)明确增加C5的5GHz配网支持。因此可以设为正式技术验证路线，但不等于任意手机、任意版本App和5GHz信道均已验收。
- 无板载按键，不再要求新增按键/串口配网指令作为启动配网前置；按已确认的开机组合条件进入。换路由器时可在无SIM情况下重新开机触发同一判断，USB维护仍作为开发诊断入口。配网失败不擦除出厂身份、设备编码、运行记录或上一有效Wi-Fi凭据；完成新连接后再原子更新凭据。
- SmartConfig期间Wi-Fi可能中断，TTL应答和快照继续运行；4G是否承担此时云端通信按选路策略验证。配网结果区分“收到密码”“连到路由器”“连到平台”。

启动判定与验收：

| SIM检测 | Wi-Fi可用 | 本版行为 |
|---|---|---|
| 明确未插卡 | 是 | 使用Wi-Fi，不进入配网 |
| 明确未插卡 | 否 | 进入SmartConfig，显示配网状态并引导打开小程序；台架首轮用官方App |
| 已插卡 | 是 | Wi-Fi优先，4G备份 |
| 已插卡 | 否 | 尝试4G；失败诊断/重试，不擅自改成无卡配网 |
| 状态未知/模组未就绪 | 否 | 完成或有界重试SIM检测并报告原因，不把未知当无卡 |

验证手机在5GHz SSID上发起、模块完成配网/重启重连/平台会话；错密码、超时、权限不足、换路由器、同名双频、无卡/锁卡/AT超时和有卡注册失败。第一轮按实际路由器非DFS信道验证，其余信道矩阵再补实测。小程序引导和实际发送端另有完整链路验收，未实现前不得标完成。

### M06 4G和网络切换

- ML307R-DL的AT启动、SIM/APN、注册、信号、传输、掉线恢复和诊断均进入本版；业务协议已确定MQTT，后端集成暂缓。现有AT TCP为台架路径，最终MQTT/TLS传输实现结合实际AT固件与后端文档验证固定，不改变MQTT产品决定。
- 启动先探测AT，避免ESP复位而LTE仍开机时盲发PWRKEY。GPIO6/8的Q1反相、有限恢复次数、无硬件流控和UART溢出需要台架验证。
- 用户已确认Wi-Fi优先、4G备份。Wi-Fi不可用则切换可用4G，Wi-Fi恢复稳定后回切；切换/回切采用防抖与有界退避，具体时间通过实测固定。
- 同时只有一个主业务连接，切换不更换模块/任务身份，不重放启停指令；本地串口业务和10秒快照不依赖云端在线。
- 首版支持每模块独立认证、TLS证书/主机名校验及接入权限；云端具体接口另行冻结，不能默认旧DTU主题和47字节点位帧已被本产品采用。

验收：无卡、SIM异常、APN错误、路由器断开、平台断开、Wi-Fi和4G反复切换、SmartConfig过程中设备事件不丢失或重复执行。

### M07 二维码、身份与参数

- B1设备信息按变长原始内容保存并转交对应业务适配，不要求模块猜测类型/显示能力字段；按C6更新主板二维码，按C7回复主板索取，未激活时遵循原表二维码长度0的表达。
- 平台/模块硬件ID、设备机型、6字节设备编码、主板显示二维码内容分离管理。唯一编码和激活来源未定前，不生成具有正式业务含义的统一样例码。
- B3/B4/C5以N字节原样接收/发送，模块只管理消息封装、方向、公共状态码、长度、完整性与受控命令执行。设备业务端负责按类型解释和校验具体参数；参数内容缺少字段表不阻塞模块协议开发。
- B5网络校时转换为主板BCD时间；建议云端UTC、主板北京时间，最终确认时区后实现。无可信时间时不写虚假日期。

验收：不同设备类型/不同N长度下数据逐字节往返一致，含00/AC AC/最大允许长度；B1不因Demo长度不同拒绝合法变长内容。二维码业务按其确定格式验证，设备参数语义不作为模块转运层验收前置。

### M08 OTA、日志和维护

- 保留ESP32应用双槽OTA、型号/版本/签名/哈希校验、下载失败不破坏运行镜像、自检失败回滚与USB恢复。ML307R基带固件升级暂不纳入。
- OTA不能破坏运行快照或重放设备启动。升级窗口建议空闲/暂停时由管理员触发；工作中是否允许升级、是否允许走4G、下载流量限制仍需确认。
- 诊断至少包含固件/硬件/AT版本、activeLink、实际频段、Wi-Fi/4G信号、串口收发/校验/超时计数、当前主板状态、快照序号与年龄、复位原因和OTA状态。
- 灯使用既有GPIO低亮，D30/D33本轮为橙色；绿灯表示网络就绪，蓝灯表示对应链路MQTT已连接，SmartConfig使用Wi-Fi橙灯闪烁。TX/RX显示现场UART字节活动（含错误帧），不表示主板或云端已执行成功。详细状态、节奏与测灯见[板内控制清单](c5-board-control-requirements-v0.14.4.md)。
- 维护保留USB日志与受控网络配置操作，恢复Wi-Fi不擦除硬件身份、设备编码或剩余时间记录。

## 5. 状态、持久化与云端契约

三组状态分别记录：网络（配网/联网/离线）、主板运行（未知/空闲/运行/暂停）、恢复（无快照/已核对/待确认/冲突）。不能把“云端离线”变成“设备已停止”，也不能把“主板空闲”直接解释为“旧任务正常结束”。

持久化建议分开存储出厂身份、网络凭据、设备编码/二维码、运行恢复快照、云端命令执行记录与有限待上报事件。各区域独立版本与清理规则；旧DTU配置revision/pointCode仅作为后续参考，不作为本版必需模型。

云端业务通道确定为MQTT；候选事件为module.status、device.state、device.event、command.result、recovery.snapshot、ota.progress。具体主题、载荷字段、应用ACK、认证、激活和绑定流程等待用户整理的后端文档，当前暂缓实现。云端语义命令映射至具体A/B指令，不直接暴露任意hex透传。

## 7. 现有仓库的沿用边界

可复用身份权限基础、日志/部署经验和可靠控制原则；现有通用DTU点位、Modbus配置、二进制遥测与模拟器不自动成为本模块的线协议。平台和旧contracts代码保持现状，待本模块云端接口确定后另行实施适配；不能将旧后端骨架称为模块云端已经可用。
