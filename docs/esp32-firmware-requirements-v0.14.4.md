## 1. 目标、依据与优先级

交付运行在 ESP32-C5 上的 DTU 固件，实现现场数据采集、可靠上报、受控写入、配置同步、网络恢复和 ESP32 OTA。业务倍率、单位、枚举、权限与租户归属由平台管理，固件执行已发布配置。

依据优先级：本轮用户确认 > 本次采购决定与定版 PCB 实际连接 > 已有具体协议契约 > 旧总体设计。历史说明中与当前连接不符的内容不能直接用于驱动开发。

状态用语：

- **事实**：定版资料或现有代码可核对；不等于真机验收。
- **既有约定**：仓库原开发计划记录的产品范围；本轮硬件变化可能需要重新确认。
- **建议**：本文提出的实现或验收基线，等待确认或技术验证。
- **待确认**：影响产品范围、体验、数据完整性或交付顺序的选择。

### 2.2 必须以当前网表修正的旧说明

1. **三种现场接口是一条共享业务通道。** U1 的 FIELD_TX 同时进入 RS485、RS232 和 TTL；FIELD_RX 来自 U12 的三输入与门。一次只连接一组现场接口。`serial.port` 表示所接接口和 DE 策略，不能实现硬件电气隔离或三口独立通信；不能可靠自动识别所接接口。
2. **TTL TX 不是旧文档描述的固定 5V。** 当前路径是 U1 GPIO23 → R35 100Ω → J3.2；没有该路径上的 5V 升压/电平转换器，因此按 3.3V 输出分析。TTL RX 是 J3.3 → R36 330Ω → U12.6，电平容限和目标设备门限另行核验；不得把整个 TTL 口泛称“3.3V/5V 全兼容”。这是网表推导，首板须测量。
3. **没有板载实体按键。** 当前 PCB 的 104 个器件实例与导出工程中均未见 SW 位号。J6 保留 EN/BOOT，J7 保留 LTE BOOT 治具接口；旧文档中的 SW2/SW3/SW4 不属于当前装配。不能把“长按板载按键配网/恢复”写成已有功能。
4. **三组 P 脚均接 VIN_IN。** 它们是公共主电源入口，不是外设 5V 输出，也没有三路独立供电来源检测，不能通过 P 脚判断现场接口种类。
5. **LTE STATE/NETLIGHT 和卡检测未连接到 ESP GPIO。** U2.25、U2.16 未接出；SIM 检测不应按旧稿做 GPIO 中断。状态通过 AT 响应、URC、心跳超时等确认；未实测前不承诺 SIM 热插拔。
6. **没有 ESP 可控的 LTE VBAT 独立断电开关。** 固件可使用 PWRKEY/RESET 恢复，不能声称能切断模组电源。U5 的输入来自 VDD_4G，整板断电恢复需要外部操作。

上述连接已对照制造基准 `.epro2` 的 PCB 段与保存重开快照。文件与主要连接的核对证据见[硬件映射](esp32-v0.14.4-hardware-map.json)。

|---|---:|---:|---|
| 现场 TX | 23 | 21 | FIELD_TX |
| 现场 RX | 24 | 23 | FIELD_RX |

| LTE 复位驱动 | 8 | 10 | MCU_LTE_RESET，经 Q1 反相 |
| ESP 橙/绿/蓝灯 | 2 / 4 / 5 | 4 / 17 / 16 | D30/D31/D32，低亮 |
| LTE 橙/绿/蓝灯 | 7 / 9 / 25 | 9 / 11 / 26 | D33/D34/D35，低亮 |

| PSRAM 相关 | 15 | 19 | 当前未接出，禁止另作普通 GPIO |

建议将两个 HP UART 分别用于 FIELD 和 LTE，应用日志走 USB Serial/JTAG，UART 控制器编号在 BSP 中固定。GPIO11/12 已用作灯，应用不得把默认 UART0 日志送到这些管脚；UART0 用于业务时需要重映射。LP UART 不作为首版必需资源。参考[UART 驱动说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c5/api-reference/peripherals/uart.html)与[USB 控制台说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c5/api-guides/usb-serial-jtag-console.html)。

初始电平：DE=0；LED 先置高再设为输出；Q1 驱动默认低，避免误触发开关机/复位。按 Q1 NPN 接法，MCU 高电平使对应模组控制脚被拉低，不能将模组端“低有效”直接写成 MCU 输出低。GPIO3/7/25 等涉及启动采样或复用，首板验证上电和复位期间的波形；应用初始化不能修复启动采样阶段的硬件问题。

## 4. 功能需求与验收

### FW-01 启动、板级驱动与自检

- 启动顺序：安全电平 → USB 日志 → Flash/PSRAM/分区检查 → 出厂身份与有效配置恢复 → 本地采集 → 联网及云端同步。
- 不等待互联网才能采集已有有效配置；首次无配置时不主动发送现场写请求。
- 记录硬件型号、固件版本、构建标识、实际 Flash/PSRAM、复位原因、运行时长和最小空闲内存。启动失败进入可维护状态，不能无限快速重启。
- 提供逐灯、UART、DE、LTE AT 等独立诊断项；现场写测试必须显式触发，不能在正常自检中自动控制设备。
- 验收：无网络、无 SIM、无配置均能完成基础启动；首板反复上电不出现主动误写，J6 可刷写和输出日志。

### FW-02 Wi-Fi 与联网策略

- 保存 SSID/密码，支持 DHCP、DNS、网络重连；首版建议仅支持家庭/工业路由器常见的个人认证网络，企业 802.1X、强制网页登录不默认包含。
- 网络就绪、DNS 成功、TLS 成功、MQTT 认证成功分别作为状态，不能用“路由器已连接”代替“平台在线”。
- 若 Q01 采用双链路，提供 WIFI_ONLY / LTE_ONLY / AUTO；建议 AUTO 为 Wi-Fi 优先、4G 备份。建议连续不可用 30 秒后切换，Wi-Fi 连续恢复 120 秒后回切，参数可配置并有防抖。
- 同一时刻仅一个主动 MQTT 连接；切换需关闭旧会话再连接，保持待 ACK 数据身份不变。切换不触发现场重写或重置配置。
- 验收：路由器断电、密码错误、DNS/Broker 不可用、两链路反复变化均有明确错误和恢复；恢复后不重复执行控制。

### FW-03 ML307R 管理与蜂窝传输（范围待 Q01）

- AT 接收支持异步 URC、分段、粘包、超时和二进制载荷；AT 管理与业务采集不能互相阻塞。
- 启动先探测 AT，避免 ESP 单独复位后对已开机模组再次盲发 PWRKEY。探测失败按受限恢复状态机处理。
- 建议控制时序：VBAT 稳定等待至少 500 ms；模组端开机低脉冲取 2.5秒，位于手册 2～3.5秒区间；RESET 低脉冲不少于 300 ms。MCU 经 Q1 反相驱动。以上待首板核验，不用“至少2秒、无上限”描述开机脉冲。
- 正常关机与开机是不同操作，禁止用同一盲目切换动作重试；连续恢复次数设上限，保留失败计数和人工恢复入口。
- 维护 SIM 状态、运营商、注册、信号、APN、数据连接和最近错误；IMEI/ICCID 仅在授权诊断时脱敏展示。SIM 缺失/锁卡/注册拒绝须分别显示；默认不尝试 PIN，避免耗尽次数。
- 当前没有 RTS/CTS 接线；不启用硬件流控。AT 波特率先以 115200 候选验证，实际设置与断电保存行为按到货 AT 固件核对。
- **蜂窝传输路线设技术验证任务，不交给用户选择库名。** 优先验证模组 AT socket + ESP 侧统一 MQTT/TLS 的可行性，同时验证模组原生 MQTTS、HTTPS 分块下载能力；若选 PPP，必须先证明 ML307R 当前固件支持并完成适配。不能假定 esp_modem 原生支持该型号。最终只固化一条量产主路线。
- 无论路线如何，都须验证 QoS1、二进制 4096字节、最大配置消息、CA 与主机名校验、SNI、异步下行及 OTA。现有 esp_modem 文档提供扩展机制，并提醒 UART 与 TLS/OTA 下的溢出风险，参见[官方说明](https://github.com/espressif/esp-protocols/blob/master/docs/esp_modem/en/README.rst)。
- 验收：记录到货 AT 固件版本；无卡、弱网、欠费/注册失败、掉线、URC 与应答交错，以及“ESP 重启而 LTE 未断电”均可诊断和恢复。超过软件恢复能力时提示整板断电。

开关机时序依据[中移物联网 ML307R 硬件设计手册 §3.9](https://atta.szlcsc.com/upload/public/pdf/source/20250926/81203B9442B53DF38E1C5C846E7C6057.pdf)。具体 MQTT/SSL/HTTP AT 手册与到货固件版本仍需补齐，硬件手册不能替代 AT 兼容性验收。

### FW-04 现场串口与 Modbus RTU

- 配置 RS485/RS232/TTL、1200～115200 波特率、8数据位、1/2停止位、NONE/EVEN/ODD；实际可接受配置需校验总线负载。
- RTU CRC、帧间隔、超时、异常响应、错误从站号/功能码、短帧/噪声、迟到帧均须处理；按事务关联响应，不能把上一次迟到应答用于下一点。
- RS485 发送前置 DE=1，确认最后停止位发完才置 DE=0；超时/取消/复位路径保证回到接收。RS232/TTL 工作时 DE 始终为0。
- 一个串行事务队列；控制优先但采集有保底机会。建议读取超时500ms、最多额外重读1次，作为测试基线；真实设备可调。写入不做盲目自动重试。
- 现有契约子集：读 FC01/02/03/04；写 BOOL→FC05、16位→FC06、32位→FC16；UINT16/INT16/UINT32/INT32/FLOAT32/BOOL；16位 AB，32位 ABCD/BADC/CDAB/DCBA。
- 零基协议地址；不默认支持 FC15、寄存器 BIT、掩码写、广播写、多步控制。旧总计划更宽的功能码列表不代表当前契约已支持。
- 允许基于相同从站/功能码/周期优化连续读，禁止跨未定义地址或假定设备允许大范围合并；首个里程碑可逐点读，须通过负载校验。
- 验收：三接口分别接测试从站，验证16位、32位字节序、BOOL、写响应及关联回读；额外覆盖 CRC 错、超时、异常码、断线与恢复。真实设备验收另需 Q05 资料。

### FW-05 配置下发与恢复

- 复用 `contracts/control-v1.md`、`config_v1.py`、`control-v1.schema.json`；现有契约仍为草案。C/C++ 与 Python/TypeScript 共享向量通过后冻结。
- 支持1～128点；规范化执行配置上限32768字节，校验 SHA-256、字段集合、重复 JSON 字段、类型、revision、有效期、地址范围、接口能力及调度负载。
- 32768是哈希输入上限，**不是 config/set 完整消息上限**。建议完整 UTF-8 config/set 上限40 KiB，必须在三端、MQTT 缓冲、分片重组和蜂窝路径统一冻结；其他控制消息按现有1024字节上限。
- 提交顺序：写备用配置记录并校验 → 暂停/排空相关事务 → 原子切换有效 revision → 回复 APPLIED。配置失败保留上一有效版本。
- 同 releaseId 同内容只返回既有结果；同 ID 不同内容拒绝。相同/较低 revision 不覆盖现用配置；服务端回退通过发布更高 revision 完成。
- 切换时取消尚未执行的旧配置命令；已经发出的写入先记录事实，不假定取消能撤销外部动作。旧采样保留原 revision，不混入新帧。
- 无配置支持静默待配置状态；已有有效配置在过期发布窗口之后仍可继续运行，expiresAt 限制新发布接收，不是配置自动失效时间。
- 验收：配置保存、指针切换和回复前后分别断电；重启只恢复完整旧版或新版；云端收到 APPLIED 必须对应已持久生效的版本。

### FW-06 采集、遥测与可靠补传

- 按采集周期生成原始值与质量码；读失败上传异常质量和空值，禁止以0或旧好值冒充新采样。倍率、偏移和业务枚举在服务端转换。
- 遥测严格遵循 `telemetry-v1.md`：47字节固定头、每点10字节元数据、网络字节序、最大4096字节、1～128点且帧内 pointCode 唯一；异常浮点值拒绝。
- 每次启动生成新 bootId，sequence 从1递增；缓存重传保留原 bootId、sequence、revision、采样时间和值，只按契约调整补传标记。已交付批次去重后仍可安全重发。
- ACK sequence 是十进制字符串；MQTT PUBACK 仅代表 Broker 收到，只有应用层 STORED 才释放对应记录。ACK 可按身份释放对应批次，不能误删后续或其他启动会话的数据。
- `REJECTED` 不无限堵住正常队列：保留受限诊断记录并隔离该批次，报告丢弃原因和数量；未知 revision 先触发云端同步，具体错误重试分类需加入契约。
- 建议Flash环形日志使用长度/校验/提交标记抵抗掉电，配合磨损均衡；RAM/PSRAM 用于缓冲，不视为掉电存储。采样写入批次与最大掉电尾部损失需要 Q07 决定。
- 缓存设置容量、年龄、满载策略及丢弃计数；建议历史遥测满时覆盖最旧未确认记录并告警，命令去重记录不能一起覆盖。是否允许此丢失由 Q07 确认。
- 补传限速并给实时状态/控制留带宽；不依赖“永远只等待最旧坏包”阻塞实时业务。重试沿用模拟器2/4/8/16/30秒，之后60秒，加入有界随机抖动；重连立即尝试。
- **采集频率与上报频率不是同一个参数。** “1秒采、5秒上报”若要保存五次采样，应发送多个合法帧；现有协议不能在同一帧重复同一点。若只上报最新值，必须确认允许丢掉中间四次采样，见 Q06。
- 验收：断网继续采集，重启继续补传；ACK丢失/重复/乱序不误删，旧revision数据可解释；满载行为、损坏记录恢复与最大尾部损失可量化。

### FW-07 控制执行与防重

- 仅执行有效身份连接收到的本机命令，执行前核对截止时间、可信时钟、appliedRevision、pointCode、类型、raw值范围和写权限。
- 首版只支持绝对值设置。离线不接收新远控；重连不能执行已过期命令；现场安全联锁由 PLC/控制器承担。
- 持久记录 commandId 与阶段，再启动外部写入。重复到达返回已有事实；同 ID 载荷冲突拒绝。
- 掉电时可能已写入但尚未记录结果，重启后标记“结果不确定”，不得自动再写；对可读映射可做只读核查，但不能仅凭值相等声称上次写入已执行。对外状态/错误映射在契约冻结任务中补齐。
- 按现有契约回复 RECEIVED/EXECUTING/WRITE_ACKED/VERIFIED/FAILED/REJECTED；平台的 UNCONFIRMED/EXPIRED 不直接冒充现有线协议枚举。
- VERIFIED 必须来自该命令关联的回读，具备类型匹配、误差策略及有效观察时间；W-only 点止于 WRITE_ACKED。FLOAT32 回读误差规则在协议冻结时明确。
- 建议命令默认有效期30秒、允许最大未来窗口120秒；去重至少24小时且最多1024条候选，结合平台最长重投窗口及实际写入频率测算。记录空间不足拒绝新写入，不能删除仍可能重放的记录腾空间。
- 验收：同命令重复100次只触发一次正常写事务；写后丢回复、执行中断电、队列中过期、配置切换等不盲目重写；不能承诺跨外部设备副作用的通用“恰好一次”。

### FW-08 时间、身份、MQTT 与平台协作

- 使用既有 `iot/v1/gateways/{gatewayId}/...` 主题族；QoS1；命令/配置/OTA下行禁止依赖 retained 命令。设备仅订阅自己的下行主题。
- 每设备独立接入凭据；硬件身份、平台业务归属、一次性认领码分离。恢复网络配置不得自动删除出厂身份或改变租户归属；解绑/转移由平台授权流程处理。
- TLS 验证 CA、主机名和有效期；不以跳过证书验证解决首次联网。凭据不能写入公共仓库、通用固件或普通日志。
- 时间保存 UTC，超时使用单调时钟。未校时时遥测 timestamp=0且清除时间可信标记；不把1970年或上次启动的时间当当前采样时间。
- 首次校时与 TLS 时间校验需要专门启动方案：保留可信时间下界，结合可用网络校时来源和认证校时方案，明确可信度；时间明显异常时拒绝时效控制及配置更新，继续旧配置采集。具体方案须在联网技术验证中实现，不能只列“联网NTP即可”。
- 建议心跳30秒、平台离线判定90秒；这是候选产品参数。LWT与平台租约配合，不能因旧 retained online 状态恢复在线。
- status/heartbeat 上报：固件/硬件版本、activeLink、appliedRevision、uptime、timeQuality、Wi-Fi/LTE信号、采集错误、缓存待发/丢弃数、复位原因、最近错误；不含明文凭据。
- 状态、心跳、OTA、身份注册、凭据轮换、时间同步和配置结果查询尚缺完整三端契约，开工后应补 schema 与测试向量。
- 验收：错证书/主机名、未知时间、凭据吊销、越权主题、重连旧消息均按预期拒绝或恢复；Broker ACL需服务端共同完成。

### FW-09 本地配置、恢复与维护

- 建议首次未配置时限时开放 SoftAP，设备独立密码/证明码与标签二维码；手机用本地页面设置 Wi-Fi 和基本网络参数，完成后关闭入口。完整流程由 Q04 确认。
- 当前无独立按键。建议 USB 授权维护命令始终作为恢复入口；离线现场再次配网可选明确的上电维护窗口或后续确认的 BOOT运行时操作。BOOT兼作下载启动脚，不能在未验证前承诺长按操作。
- 普通网络掉线不自动清空凭据、不无限开放无密码 AP。恢复网络设置和整机业务清理分开；擦除身份必须走独立出厂工序。
- 配置分为出厂身份、网络参数、云端业务快照、诊断参数；只允许云端业务快照改变现场映射，避免本地修改和云端版本漂移。
- USB 维护至少支持查看状态、导出脱敏日志、网络配置、开启限时配网、LTE诊断、重启、清除网络设置。危险写入与恢复操作需明确操作反馈。
- 验收：首次使用、换路由器、错误密码、平台不可达和遗忘网络信息均有恢复路径；恢复不丢失硬件身份，业务命令不从未认证AP入口执行。

### FW-10 ESP32 OTA

- OTA对象明确为 ESP32 应用；ML307R 固件升级另建需求。清单含任务ID、目标型号/硬件兼容范围、版本、大小、SHA-256、签名、URL和有效期；重复任务不重复安装。
- 使用双OTA槽，下载到非运行槽，验证型号/镜像/签名/哈希/大小后切换；断网或断电不破坏当前可启动应用。
- 新固件启动完成限定时间内的本地自检，确认存储、配置可读、任务可运行后标记有效；不能仅因没有SIM/云端短时不可达就永久升级循环。自检失败或确认前崩溃回滚。
- OTA期间拒绝新现场写入并处理已执行事务；明确是否继续采集、缓存占用及暂停时段上报。网络切换时建议终止本次传输并重试；HTTP Range 断点续传作为可选优化，首版不预先承诺。
- 4G下载需要流量/漫游/弱网策略，见Q09。候选为管理员明确触发，默认不开启无提示自动蜂窝升级。
- 首板开发阶段保留USB恢复能力；Secure Boot/Flash Encryption/eFuse生产策略须在烧录流程定版时评审。OTA签名校验不自动等同于已开启全套不可逆芯片安全设置。
- 验收：有效升级、错误型号/签名/哈希、空间不足、下载各阶段断电、首次启动崩溃、回滚后旧配置可用，且仍可通过J6恢复。

双槽与应用自检回滚依据[ESP-IDF ESP32-C5 OTA说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c5/api-reference/system/ota.html)。

### FW-11 指示灯与诊断

本次D30/D33实际为橙色，不能在本轮用户说明中称其为红灯。以下为建议语义，见Q10：

| 灯组 | 建议含义 |
|---|---|
| ESP橙 | 启动/重要故障；通过固定闪码区分 |
| ESP绿 | 设备服务正常；连接平台后常亮，连接中慢闪 |
| ESP蓝 | 配网/维护，慢闪；OTA时使用另一明确节奏 |
| LTE橙 | SIM/AT/注册错误 |
| LTE绿 | 注册中慢闪，注册成功常亮 |
| LTE蓝 | 蜂窝成为当前业务链路时亮；不等同于平台已连接 |
| TX/RX | 现场真实字节收发，建议50～100ms脉冲；不显示Wi-Fi/LTE流量 |

灯由 ESP 软件统一控制，不根据其靠近LTE就假定由模组状态脚驱动。日志保留错误码、阶段、计数和脱敏上下文；诊断不能阻塞串口任务。首板需要提供供电复位、堆内存、UART溢出、采集成功率、补传队列和OTA进度证据。

## 5. 存储、性能与容量预算

### 5.1 分区草案

8 MiB Flash 的预算建议：OTA0/OTA1 各2.5 MiB，遥测环形缓存约2 MiB，其余约1 MiB容纳 bootloader/分区表、NVS/密钥、otadata、双配置记录、命令去重日志、诊断及对齐预留。不额外承诺 factory 应用槽。

这不是可直接烧录的分区表。里程碑A以实际镜像大小、对齐要求和掉电策略编制 partition CSV；如镜像超过槽预算，先重新评估缓存与功能，不能挤占备用OTA槽。PSRAM只扩充运行内存，不能扩大持久容量。

### 5.2 离线时长估算

以20个4字节好值在一帧为例：47 + 20×(10+4) = 327字节，尚未计日志头、CRC、对齐、元数据与保留空间。

| 保留策略 | 理想数据量/小时 | 理想2 MiB可容纳时间 |
|---|---:|---:|
| 每1秒保留一帧 | 1,177,200字节，约1.12 MiB | 约1.78小时 |
| 每5秒仅保留一帧 | 235,440字节，约0.225 MiB | 约8.91小时 |

实际时间更短，取决于点类型、失败记录、写入粒度和磨损管理。若要求20点每秒全量、离线24小时不丢数据，仅原始帧就约26.9 MiB，当前8MB Flash无法按上述原始格式保证，需要降频/压缩验证或修改硬件存储。Q06/Q07必须一起确认。

### 5.3 非功能验收建议

- 初始负载基线：一现场设备、20点、1秒采集；上报与样本保留策略待Q06。128点是协议上限，不能推导128点均可100ms采集。
- 根据实际波特率、请求/响应字节数、帧间隔、从站处理时间、超时和重试估算总线占用；建议常态预算不超过70%，不可执行的配置明确拒绝。
- 测试从站正常、9600 8N1、20点基线下，建议已接收命令至写响应P95≤2秒；云端端到端延时单独记录，不对弱网或真实设备无条件承诺。
- 建议先24小时冒烟、再72小时连续运行；记录重启数、堆内存趋势、UART溢出、采样延期、丢包/缓存丢弃及网络恢复次数。
- 可靠性测试覆盖至少20次采集/缓存/配置/命令/OTA关键时点故障注入；按场景单独记录次数和结果。未确认的掉电窗口不能标记“零丢失”。

## 6. 架构与工程交付

建议 ESP-IDF + C/C++ + FreeRTOS；固定 `esp32c5`，锁定经过验证的 ESP-IDF 精确版本、工具链、组件版本和 sdkconfig，不直接继承旧S3工程参数或无约束 latest。

| 模块 | 责任 |
|---|---|
| board / diagnostics | 引脚、安全初值、USB、灯、复位原因、维护入口 |
| serial_bus / modbus | 共享业务UART、DE、事务、CRC、调度、基础类型解码 |
| modem / network | AT解析与URC、蜂窝恢复、Wi-Fi、选路、时间来源 |
| identity / mqtt | 出厂身份、TLS、主题、会话、订阅与消息大小限制 |
| config / codec | schema、哈希、版本原子切换、C/Python/TS一致性 |
| telemetry_store | 采样组帧、Flash日志、ACK、防重与补传限速 |
| command | 过期/权限校验、持久去重、串行写入与关联回读 |
| ota | 清单校验、下载、镜像验证、自检与回滚 |

串口事务、网络收发、Flash持久化、OTA与维护使用有界队列/缓冲；业务写入单一执行者；不能在网络回调里直接做Modbus事务或长时间擦Flash。

交付：固件源码、可复现构建说明、固定依赖、分区表、BSP映射、通用镜像及逐台身份写入工具、协议向量测试、首板诊断固件、量产固件、刷写/配网/恢复/OTA手册、测试记录与已知限制。本轮只整理需求，未创建或验收上述实现。
