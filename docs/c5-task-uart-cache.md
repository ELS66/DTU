# ESP32-C5 任务监督、串口恢复与原始参数缓存

日期：2026-10-20；固件0.6.0-dev；硬件V0.14.4；ESP-IDF 5.5.1。本文描述已编译的软件及首板验收方案，尚未烧录或进行实物故障注入。验证记录见[本轮证据](c5-supervision-evidence.json)。

## 1. 任务推进监督与看门狗

独立supervision任务每100ms检查任务最近一次推进时间，只有所有已启用任务均在预算内才喂module_progress看门狗用户。CPU0空闲任务继续受SDK监督；运行时将TWDT重配置为5秒、超时panic并重启，不依赖SDK默认的“只打印”设置。

| 任务 | 推进点 | 无推进预算 |
|---|---|---|
| field_uart | 每轮收发处理完成后进入下一轮；无主板也能按时处理超时与轮询 | 15秒 |
| runtime_store | 前次记录评估/提交返回，完成250ms等待后 | 10秒 |
| indicators | 状态采样、灯渲染及需要的GPIO输出完成 | 2秒 |
| network | 一轮事件、超时、配网/重连、配置保存与状态发布完成 | 15秒 |
| modem_at | 一次有界AT事务及错误排空结束，或一轮空闲处理完成 | 45秒 |

AT接收pump不喂进度，因此持续收到无关字节不能掩盖事务不能结束；正常30秒附着/激活等待在45秒预算内。任务创建之前启用对应预算，创建失败明确停用；未成功初始化的网络或存储仍由各自错误诊断报告，不制造反复重启。没有独立任务的uplink与临时USB/probe任务不在此5项中，不能将本机制视为所有应用路径的完整覆盖。

任何预算到期都锁存故障位图，随后即便任务恢复也不重新喂狗。SDK TWDT随后触发panic/复位，延迟约不超过5秒加调度误差；当前不执行任务热重建、不清配置、不改历史、不向主板发送启停。复位后的启动仍只自动查询B2。

位图bit0～4依次为field_uart、runtime_store、indicators、network、modem_at。第一次检测故障后将魔数、格式版本、位图、启动后时刻和CRC保存至RTC noinit，下一次启动读取到status后清除RTC槽。它是上次故障上下文，不等同于复位原因；reset_reason单独显示。RTC信息不能承诺跨断电保留；CPU完全占死使supervisor无法执行时，也不能保证留下任务位图，此时主要依赖SDK复位原因与panic输出。未写入Flash故障日志。

预算是当前台架参数，需要首板测量调度、日志、NVS耗时后固定。调试器停顿、OpenOCD暂停硬件看门狗等行为不能作为真实卡死验收。

## 2. 现场UART异常与恢复

UART0仍为9600 8N1，驱动RX环形缓存8192字节、TX4096字节、事件队列16项。每轮在读取前后收集驱动事件，每次最多处理32项，避免事件风暴令处理循环无限占用。

- FIFO溢出、接收环形缓存满、帧错误、奇偶错误、BREAK、读失败，均按不可信接收内容处理。8N1关闭了奇偶校验，parity通常为0，但保留统计入口。
- 队列占用达到12/16记一次压力采样；仅高占用不丢合法帧。观察到16/16时，因SDK可能已丢失错误通知，保守视为数据可能损坏并进入恢复。
- SDK公开接口没有精确的事件丢失计数，queue_peak/pressure/queue_full是采样结果，不能当作实际丢事件总量，也不能保证捕获所有瞬间满队列。
- 错误后丢弃本轮读出的字节与驱动待处理接收、清除部分协议帧、取消在途请求并计aborted，默认500ms排空保护。后续新字节继续延长发起下一条请求前的排空间隔。
- 已排入TX驱动的字节可能仍会发出；取消等待不表示主板没有执行。A1/A2/A3/A4/B4不自动重放，控制结果仍可能未知。
- 仅在错误保护时间已过且收到合法匹配回复或合法主板事件后，才记一次恢复并清连续错误数。任意字节、错校验、无关/迟到回复不算恢复。
- 部分帧的错误丢弃另记discarded_partial，不冒充帧间超时；每种错误数表示包含该类型的一批恢复处理，合并同一批内的重复驱动通知，不等同于硬件中断数。
- 连续故障期间只打印首次故障日志，各计数继续更新，防止日志风暴。处理错误本身不触发ESP复位；只有任务停止推进才由看门狗处理。

RX灯在解析前显示真实接收到的字节，也显示被保守丢弃的接收数据；协议是否成功另查计数。TX灯规则保持已确认方案。

B1/B3回复具有变长N字节，回复预算按最大4096字节完整帧计算。请求8字节、处理超时默认500ms时，等待预算为4776ms，包含请求与回复的9600 8N1线速时间；B2为521ms。B4最长请求同样计入发送时间。不是固定等待4776ms才接受回复，完整合法回复到达即结束。即使放宽等待，协议无事务ID，仍无法彻底排除同命令迟到歧义。

## 3. 按N字节缓存主板信息与参数

本轮提供两个相互独立、有界的RAM槽：

| 槽 | 来源 | 保存内容 |
|---|---|---|
| info | 成功匹配的B1回复 | 除首字节公共状态码以外的原始N字节 |
| params | 成功匹配的B3回复、合法C5事件 | B3去掉公共状态码后的N字节；C5全部N字节 |

每槽包含known、存储格式版本1、内容revision、长度、CRC32、来源命令、最近观测启动毫秒和面板参数事件版本。空N与unknown可区分；保留00、AC AC和任意二进制字节。最大槽容量4089字节，B1/B3因帧内状态码最多4088字节，C5可到4089字节。格式版本是模块缓存格式，不是猜测主板参数内部版本。

唯一UART任务写缓存，互斥量保护完整替换和完整读取；拒绝越界、非法来源、时间/事件版本倒退和内容revision溢出，原快照保留。相同字节只更新观测/来源，不制造内容revision；变短会清除旧尾部。内容变更才计算新CRC。

B3发出时捕获C5事件版本，期间C5更新后，较早B3回复不覆盖params，stale_param_reply增长；相同参数的C5也会刷新事件版本。溢出时停止接受可能有歧义的更新并报告失败，不回绕。B4发送内容不能直接当成主板已应用结果，因此不写入缓存。

C5在RAM缓存成功后返回状态01，缓存失败返回00。该ACK不表示写入Flash或云端确认，不构成可靠事件队列。本轮未增加B1/B3自动启动查询，保留启动只查询B2；台架通过device type、device params触发读取。

缓存重启为空；失联后仍保留最近一次RAM观测，observed时刻用于判断年龄，不能当作已确认当前参数。当前不会自动将缓存回写到主板，也没有多设备或更换主板身份绑定。Flash持久化、C5完整事件日志和离线上报仍列为后续事项，分区与36字节余时记录格式均未改变。

## 4. USB诊断

status新增WATCHDOG、逐项TASK、UART_HEALTH、CACHE_DIAG及两个CACHE摘要。TASK enabled=0表示任务未创建或未启用，不能解读为健康运行；advances与age辅助判断推进。

| 命令 | 用途 |
|---|---|
| device type | 发送B1查询；成功后更新info |
| device params | 发送B3查询；成功且未被新C5超越后更新params |
| cache info | 读取info元数据和前64字节HEX；不触发UART请求 |
| cache params | 读取params元数据和前64字节HEX |
| cache params 64 256 | 从偏移64最多导出256字节；末尾自动缩短 |
| status | 查看任务预算、上次故障上下文、UART恢复/压力及缓存摘要 |

每次导出使用一个完整快照。多次分段读取之间参数可能变化，收集者必须核对revision、长度和CRC一致；不一致时重新导出。没有清空、恢复出厂、故障注入或缓存回放控制台命令。

## 5. 已完成的软件检查与首板验收

共享生产C核心累计23380项检查通过，包括90秒任务推进模拟、30秒AT间隔不误报、任务未被调度/超时/故障锁存/停用/时钟回退、UART错误合并/保护时间/恢复/饱和计数、损坏分片不拼接、所有0～4089字节缓存长度/CRC/二进制内容、重复与变短更新/拒绝后保留、C5超越旧查询和双向线速预算。ESP-IDF 5.5.1交叉编译通过，镜像995488字节，3MiB应用槽约68%空闲。

这些检查直接使用生产核心策略，但不覆盖真实任务调度、FreeRTOS互斥竞争、RTC保留、UART驱动事件丢失或实际TWDT复位。首板须补：

1. 无主板、无SIM、Wi-Fi失败，持续运行并操作USB，确认超时/配网发生而任务监督不误复位。
2. 对5个任务分别在专用台架测试构建中插入超过预算的阻塞，观察故障位、停止喂狗、实际复位、下一次诊断与主板不被自动启动。CPU忙死另验SDK空闲任务保护，不用全CPU调试暂停代替。
3. 正常30秒附着/激活、长串口发送与NVS写入并发，不误判；验证最高日志量下LED2秒预算。
4. 串口噪声/错误波特率/BREAK/突发流量，检查错误、取消在途、部分帧丢弃、500ms保护及恢复计数，无自动控制重放。帧/奇偶错误需要合适信号源，不以普通TTL拆包替代硬件注入。
5. 4096字节长帧、RX满缓存/事件队列压力与Flash并发，验证真实吞吐和丢弃边界；确认TX/RX灯和主板失联诊断可解释。
6. 不同设备N长度、00/AC AC、空正文、最长C5与B1/B3，逐字节对比导出长度与CRC；旧B3与新C5交错，前者不得覆盖。
7. 高速读cache与C5并发，多段导出检查revision；重启确认缓存unknown、历史余时仍独立恢复、无参数自动回写。
8. 参数缓存失败/内存不足、NVS不可用、任务创建失败，分别核对错误与停用状态；RTC诊断再做软件复位和断电边界测试。
